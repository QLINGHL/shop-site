# USDT(TRC20) 收款接线方案（待他确认后即部署）

状态：方案已定稿，未开工。等他两件事：① 确认拿 OKX 收店里的钱；② 发 TRC20 充值地址。

## 流程（半自动，他只需要在 OKX App 点一次确认）

1. 买家在商品页点「USDT 付款」
2. 付款页显示：订单号 + USDT 金额 + TRC20 收款地址（大字+一键复制）+ 二维码
3. 买家转完，把交易哈希（TXID）贴回来提交
4. 他在 OKX App 看到账 → 后台点「确认收款」
5. 订单变 paid → 走 ji8 发货（API 通了就自动，没通就按现在的半自动）

## 地址放哪（关键安全点）

- TRC20 地址只存在服务端 `.env`（`USDT_TRC20_ADDRESS`），**不写进前端代码**
- 前端付款页通过 `GET /api/payinfo?order_no=` 实时拉地址+金额+二维码内容
- 这样换地址不用重新部署前端

## 要加的接口（Flask 脚手架已有订单表，直接扩）

- `POST /api/orders`：加 `payment_method=usdt`，`status=pending_payment`，返回 order_no / usdt_amount / address / qr_text
- `POST /api/orders/<order_no>/txid`：买家提交交易哈希，`status=tx_submitted`
- `POST /api/admin/orders/<order_no>/confirm`：他确认收款，`status=paid` → 触发发货
- 登录态沿用现有 JWT；admin 接口只认他的账号

## 金额换算（要他拍板，二选一）

- A（推荐）：他定一个固定汇率，写进后端配置；`usdt_amount = cny / rate`，保留 2 位小数
- B：下单瞬间按实时汇率算（要多接一个汇率源，多一个故障点）
- 建议 A：简单、可预测，买家看到的价格就是他定的
- **定率参考（2026-10-12 实测）**：他自己今天在 OKX C2C 第一笔买了 140 USDT，花了 ¥931，成交价 = 931/140 = **6.65 CNY/USDT**。建议固定汇率就定在他自己的拿货成本线附近（如 6.6–6.7），留一点汇率波动缓冲；定得太高（如 7.2），买家付的 USDT 比市价贵 ~8%，等于替他交隐形溢价，转化率更低。旧的 7.2 示例仅是占位，以今天这笔实测为准。
